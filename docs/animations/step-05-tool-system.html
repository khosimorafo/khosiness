Step 5 in context

What this step does

Introduce named tool contracts, a registry, workspace path checks, and structured results for read-only filesystem operations.

What it builds on

The Step 4 reference dispatches injected fake tools and records their results. Step 5 supplies concrete tools through that same interface.

Goal

Make a request resolve to a known operation, reject path escapes before the file read, and return usable evidence or an explicit failure.

End state

Tool, ToolResult, ToolRegistry, and list/search/read tools connect to the loop. Tests verify failures and bounded output. Typed arguments are validated at execution, reads support line ranges, and each discovered search target is checked. Approval policy comes in Step 9.
