2. Read state, keep history separate

The builder receives the Task and RunState. Its input includes four observations, not the JSONL event file. That file remains a durable record owned by the event store. A complete source record does not require a complete prompt dump.

3. Select the latest two

A window of two selects the search result and version-file read. The directory listing and README observation stay in state, but leave this call’s active context. An old observation can still be important: this simple policy does not rank relevance.

4. Clip each rendered observation

The reference renders each selected observation with repr(). If that text exceeds 120 characters in this demonstration, keep its prefix and add "... [truncated]". The marker is additional text beyond the cap. Source observations stay unchanged.

Clipped text is incomplete evidence. A follow-up read may be needed.

text = repr(observation)
if len(text) > 120:
    text = text[:120] + "... [truncated]"

5. Assemble three messages

The reference returns a system instruction, a user message containing task details, and a user message containing rendered observations. These observations are data; they do not acquire authority to override the task. This is a simple provider-neutral shape, not a native tool-call transcript.

The harness selects visibility. A tool result does not choose its own place in the prompt.

6. Measure the selected view

last_stats records the number of messages and the sum of their content lengths. The board computes those values from the illustrated message strings. These are characters, not tokens, and the system/task messages have no total size cap here.

Local build statistics are not emitted metrics or durable context events.

ContextStats(messages=len(messages),
