1. Separate the lifetimes
A prior investigation found a retry setting. Its events record what happened, its state records run position, and a promoted memory can help a different run. None automatically becomes the next prompt.
State, history, memory, and context have different jobs.

3. Reopen storage in a different run
SQLite makes storage independent of the original process. A new store instance pointing at the same database can retrieve the row. That is cross-run reuse, unlike loading the state checkpoint of run A.
A new run can reuse knowledge without resuming the old run.
Illustrative input / request
Run B opens the same memory.db
store.search("Retries", limit=3)
Illustrative result / state
Illustrative match: m-retry

Run A is not resumed.
Boundary trace
Run A add → close → Run B search
Store persistence is distinct from checkpoint continuity.
Knowledge survives a new store instance
4. Understand the retrieval rule
The reference filters active rows whose content matches SQL LIKE, optionally by type, and orders by updated_at descending. It does not assess meaning. Percent and underscore in a query retain LIKE wildcard semantics.
A keyword match is a candidate, not a relevance guarantee.
Illustrative input / request
search(query="Retries",
 memory_types=["semantic"], limit=3)
Illustrative result / state
WHERE status = active
AND content LIKE %Retries%
ORDER BY updated_at DESC
LIMIT 3
Boundary trace
Parameterized SQL → matching rows
Newest matching rows are not necessarily most useful.
Selection rule is inspectable
5. Exclude an inactive fact
If the repository changes, mark the old fact inactive. The reference search excludes inactive rows. It does not delete the original event history or automatically discover that a memory became stale.
Invalidate a fact without rewriting its history.

6. Bound count, then plan injection

8. Keep retrieval failures explicit
No matches means the retriever has no matching active memory. It does not mean the setting is absent from the repository. Fall back to bounded repository inspection; never invent a stored source.
An empty retrieval result is a limit of retrieval.
